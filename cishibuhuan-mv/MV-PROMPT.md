  "artist": "青鸟飞鱼",
  "line":   "电视剧《仙剑奇侠传三》插曲",

**样式（照 style-guide 的纸艺三件套做，不要做成 UI 卡片）**

- 尺寸 760×340，屏幕坐标中心 `(760, 745)`，整体旋转 `-0.022 rad`——压在合着的书的左下方，稍微斜一点，像随手放在桌上的一张标签纸

**2. 测节拍（整首）**

```bash
node scripts/analyze.mjs "/Users/xufuying/Downloads/M800000Zck7D0LPFos.mp3" --duration=263
```

把 `firstBeat` / `beatDur` 写进 `spec.beat = { t0, dur }`。**不许估**：一拍弹一下全靠它，估错整片像在打摆子。顺手用 `dips` 核对 30 句断句是否与 LRC 一致——这首鼓点偏弱（人声与弦乐为主），`dips` 会比 `beats` 更可靠。

**3. 写 `data/spec.json`**

```json
{
  "title": "此生不换",
  "artist": "青鸟飞鱼",
  "duration": 263,
  "fps": 30,
  "width": 1920,
  "height": 1080,
  "beat": { "t0": "<firstBeat>", "dur": "<beatDur>" },
  "credits": {
    "title": "此生不换", "artist": "青鸟飞鱼",
    "line": "电视剧《仙剑奇侠传三》插曲",
    "by": "词 杨漩予　曲 闻震",
    "in": 0.0, "out": 6.5
  },
  "lyrics": [ "见文末附录二，30 条，t 用绝对时间" ],
  "scenes": [ "见分镜表，35 场" ]
}
```

规则：

1. `scenes[0].t = 0`，`scenes` 与 `lyrics` 都严格递增；最后一场 `t = 240.99`，往后 22 秒由 `ending` 一场自己撑（见第 35 场）
2. **有人声的段落：每场起点必须落在某句歌词的起唱点上**，翻页才会被感知成「换句」
3. **无人声段落例外**（0–31.6 的 1–4 场、125.10 的 19 场、198.15 的 30 场，以及第 35 场 245.5 之后的收尾）：这些场不挂歌词，起点对齐乐器动机变化即可，`scenes[].kw` 写 `—`
4. `scenes[].id` 只能用桥段库 id，写错不报错、只是**静默不绘制**（整页空白）
5. 场次账要算平：**29 场挂歌词**（第 33 场把 27、28 两句并成一场）+ **6 场无人声**（1–4、19、30）= 35 场。18 个桥段里 **17 个各用两次，`ending` 只用一次**（17×2 + 1 = 35）。同一 id 第二次出现时构图必须换：换机位、换光色、换角色朝向，不能只是重播
6. `credits` 是**屏幕空间贴片**，不进 `scenes`、不跟相机缩放、不参与翻页转场；它与第 1 场并行存在，6.5s 后自己淡出
7. 建议再加一个 `spec.credits` 的可选尾卡：同一张卡在 257.5–262 以 `alpha 0.6` 浮在桌面右下角，作为「词曲 / 演唱」的收尾交代；若与合书、印章抢视线就删掉，优先保证末帧干净

**4. 渲染**

```bash
node scripts/render.mjs --stills 0.4 3 6.8 12 20 27 34 46 55 64 77 85 92 106 113 120 127 133 147 161 176 191 200 213 228 236 243 250
node scripts/render.mjs                      # 全片 7890 帧，约 24–27 分钟
node scripts/mux.mjs "/Users/xufuying/Downloads/M800000Zck7D0LPFos.mp3" --fade=1.5 --out 此生不换_立体书MV_全曲.mp4
```

全片一次跑完容易被中断，建议**分三段跑**，每段渲完先合一次片自检：

```bash
node scripts/render.mjs --from=0    --to=2630     # 0–87.7s
node scripts/render.mjs --from=2630 --to=5260     # 87.7–175.3s
node scripts/render.mjs --from=5260 --to=7890     # 175.3–263.0s
```

`--from/--to` 是帧号（秒 × 30），断点续跑不会重画前面的；但**只要改过 `props.js` / `core.js`，就必须整片重渲**。

**5. 自检**

```bash
ffmpeg -y -i out/此生不换_立体书MV_全曲.mp4 \
  -vf "select='eq(n\,12)+eq(n\,105)+eq(n\,600)+eq(n\,960)+eq(n\,1650)+eq(n\,2700)+eq(n\,3300)+eq(n\,3900)+eq(n\,4500)+eq(n\,5100)+eq(n\,6000)+eq(n\,6600)+eq(n\,7320)+eq(n\,7500)+eq(n\,7850)',scale=400:-1,tile=5x3" \
  -frames:v 1 out/contact.jpg
```

对照联系表逐格看：风格是否统一、有无空白帧 / 穿帮帧、歌词是否冲出版心、主角是否被挡住、第 1 帧是不是「合着的书」、末帧是不是「合上的书 + 印章 + 黄昏光」。

## 七、质量红线（逐条对照，别靠感觉）

- 歌词盖章前必须 `textAlign(CENTER, BASELINE)`，画完复位 `LEFT` —— 否则每个字右移半个字宽、整行冲出版心
- 开屏卡是屏幕空间贴片：相机从 1.0 推到 1.36 时它**不跟着放大**；卡上四行字左对齐、不换行、不压字，投影必须落在书封上
- 开屏卡不要做成 UI 卡片：不许圆角矩形、不许外发阴影、不许半透明玻璃——它是一张纸，靠剪纸描边和暖灰投影立住
- 合书顺序：**纸艺先纵向压平 → 封面从右侧合过来**；封面「从中间长开」会瞬间吞掉主角。第 1 场开书是这套动作的逆放
- 每 0.5–1 秒必须有可见运动；第 35 场有 20 秒收尾，靠镜头缓拉 + 纸屑 + 光色移动，不能定格
- 段与段用翻页转场（默认 0.46s），不要硬切；最后一帧不要停在半句歌词上
- 一句只演一个动作；纸艺可以挡手、挡背景，**不能整块盖住人**
- 同一 id 两次出现必须有区别（机位 / 光色 / 角色朝向任换其一），否则观众会觉得「放错片」
- 整页高饱和色不超过两种；投影只用暖灰 `rgba(92,68,46,α)`，不用黑
- 改了 `props.js` / `core.js` 必须整片重渲，只有改时间轴才能局部补帧

## 九、环境备注（先看这条再动手）

本机 `ffmpeg` 不在 PATH 里，只有 Remotion 自带的精简构建：它**没有 `s16le` muxer**，`analyze.mjs` 默认的 `-f s16le -` 会直接输出 0 字节。

两种解法，任选：

- 首选：`brew install ffmpeg`，之后一切照 skill 默认命令跑
- 临时：用自带构建解码成 wav（`-f wav`），自己按 22050Hz / 单声道 / 16bit 解析 PCM 算包络与节拍。库路径必须显式给（arm64 那个包在 x64 node 上会 bad CPU type）：

```bash
D="/Users/xufuying/Desktop/projects/opencode 工作台/my-film/node_modules/@remotion/compositor-darwin-x64"
DYLD_LIBRARY_PATH="$D" "$D/ffmpeg" -v error -y -i "/Users/xufuying/Downloads/M800000Zck7D0LPFos.mp3" \
  -ac 1 -ar 22050 -f wav /tmp/song.wav
```

`mux.mjs` 用的 `libx264 + aac + mp4` 这套参数精简构建是支持的，合片不受影响，但同样需要 `DYLD_LIBRARY_PATH`，或设 `FFMPEG=<那个绝对路径>`。
