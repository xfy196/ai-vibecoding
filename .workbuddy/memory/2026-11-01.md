1920×1080 / 30fps / 4:19 / 20MB，26 镜全部程序化绘制，渲染 4 分钟。

### 技术路线（可复用）
- **没有 ffmpeg 时**：项目里 `wangji-shijian/bin/ffmpeg` 有 6.1.1 静态版，比装 brew 快
- **管线**：PIL 在 384×216 逻辑画布逐帧绘制 → `point(LUT)` 提亮 → `resize(NEAREST)` ×5 → 管道喂 ffmpeg
- **速度**：约 33 fps，7770 帧 4 分钟。逐帧全画也不慢，不必做静态层缓存
- **像素字幕**：11px 字体渲染 → 阈值二值化（`point(v>88)`）→ paste，才有硬边。字号小于 8px 时别加描边，描边会把笔画吃掉

### 踩过的坑（下次直接避开）
1. **雾不能用 sin 函数做**：`sin(x)*sin(y)` 会变成规则斜条纹；要用低频噪声（小图 BICUBIC 放大成浓度场）+ 白噪声调阈值，才会"成团"
2. **抖动网点当虚化 = 砖墙**：`(x*7+y*13)%11` 这类规则哈希在小尺寸上放大后是马赛克墙。背景要么纯渐变，要么低频噪声
3. **像素风最容易"暗成一团黑"**：渲染完统一过一条提亮 LUT（`x**0.86*0.94+0.058`，黑位抬到 14）能救回大半暗部
4. **全屏染色做光效 = 噪点电视**：暖光只用中心光晕（几个同心 ellipse），不要铺满画面再打点
5. **`math.pow(t, 1.32)` 会因浮点截断产生负数** → `ValueError: math domain error`，所有归一化参数都要 clamp
6. **PIL `img.point()` 对 RGB 要 768 项**（`lut*3`），不是 256
7. **"画中画"陷阱**：给车内视角画纯黑 A 柱/车顶，在 1080p 上看就像"画面没铺满"。边框要窄、要有内容

## 同日：修人物"模糊"（用户反馈渲染出来的人物不清楚）

### 病根
原人物是"几个大矩形堆的"：头是一整块色，只有一条 1px 线当眼；没有轮廓、没有明暗，
和背景同色系糊在一起。不是渲染分辨率的问题（384→1920 NEAREST 不会糊）。

### 药方（新建 src/sprites.py）
1. **每个部件先铺 1px 暗色描边**（`_rect/_ell/_poly` 的 `ol=True`）—— 这是最关键的一步，人立刻从背景跳出来

3. **左亮右暗两档**：光从左边来，右半身/右脸压暗一档，像素人物全靠这个才有体积
4. **脸用多边形做瓜子形**，不要椭圆（椭圆在低分辨率下像圆球）
5. 头发要有刘海 + 鬓角 + 高光，不是一块方块
6. 加"身份符号"：给她加安全带（立刻是坐车），给他加围巾/大衣中缝

- 近景半身：h=140~168（占画面 65-78%），五官才看得见
- 中景：h=60~82
- 远景路人：h=16~18（只要能看出"在走"）
- h<50 时不要画五官，画了也是噪点

### 其他坑
- `_rect` 描边会吃掉小字号的笔画：字号 <10px 别加描边
- 玻璃倒影的横条不能糊在人脸上（第一版把 S14 的五官切碎了），只画在人物侧后方的空白区

## 同日：修"画面模糊"（用户第二次说糊，这次指的是整体）

### 关键教训：先量，再改
"模糊"听起来像分辨率问题，其实是**对比度问题**。用一行代码就能确诊：

```python
lum = np.array(img).mean(axis=2)
np.median(lum), lum.std(), np.percentile(lum,[10,50,90])
```

实测原片：中位 29、标准差 20、**90% 的像素挤在 23-47 这 24 级灰阶里**。
分辨率 1920×1080 再高也没用，整片只有一种灰蓝，看上去就是"糊"。

### 药方
1. **分段线性 S 曲线**（不是 gamma、不是线性拉伸）：在最密集的 26-47 段给 3.5 倍斜率，
   把 24 级灰拉成 80 多级。gamma 会把暗部整体提亮反而更灰，线性拉伸会压暗全片
2. **曲线要用实测数据设计**：先渲染几帧原始图（未过 LUT），统计分位，再定 knots。
   我盲目用 gain=1.55 试了两版，中位从中位 51 掉到 19，白跑两次渲染
3. **高光段要有斜率**：knots 在 140-180 之间如果太平（216→230），所有浅色物体
   （皮肤、袖口、雪）会挤成一团白。留 24 级跨度才有层次
4. **编码**：crf 19→15，加 `-x264-params deblock=-3,-3` —— 去块滤波会把像素硬边磨软

### 手的具体化（用户说"双手场景太抽象"）
- 手指必须**有缝**（1.35u 高 + 1.95u 间距），且**长短不一**（5.0/6.2/5.4/4.0）
- 拇指从掌根侧伸出，是**圆头短指**，不是尖三角（第一版像插了面旗）
- 指甲（指尖 1px 亮块）和指节阴影是"能看出是手"的关键
- 光晕不能大过手：第一版 r=66 的同心圆把整只手盖住了，收到 46 才对

### 流程教训
这一轮改了 6 次全片渲染（每次 3 分钟）。应该先写一个"单帧模拟器"：
渲染几帧原始图 → 套不同 LUT → 打印中位/标准差 → 选定参数 → 再渲染全片。

## 《富士山下》像素叙事 MV（fuji-mv）

音频：陈奕迅《富士山下》（用户 mp3），歌词时间轴取自网易云 id=65766。

### 技术栈与关键决定
- 使用 skill `pixel-story-mv`：320x180 原生画布，整数倍放大到 1080p，全部 Python/Pillow 手绘。
- 本机没有系统 ffmpeg → 用 `pip install imageio-ffmpeg` 的静态二进制，软链到 `fuji-mv/bin/ffmpeg`，engine 里 `FFMPEG` 常量指向它。
- librosa 装不上/太慢 → 自己写 `beats.py`（ffmpeg 解码 + 谱通量 + 自相关）替代。
- macOS 字体：`/System/Library/Fonts/STHeiti Medium.ttc` index=1（Heiti SC）。
- `pixtext` 必须用 `font.getbbox()` 定位，否则顶部被裁；小字号阈值要降到 96，否则细笔画断裂。

### 踩过的坑（复用价值高）
1. **动画时间必须用镜头内局部时间**。我用绝对 t 写 `sm(t, a, b)`，导致每个镜头一开场就是"已完成"状态。
   解决：`engine.Film.frame/_view` 里设 `CURRENT_START`，shots 里用 `lt(t) = t - CURRENT_START`。
2. **`im.paste(RGBA, (0,0))` 不带 mask 会把透明区变成黑色**，被 check_holes 抓到。
3. **check_holes 的"纯黑"报警几乎总是布局bug**：某个 band 只填了局部（座椅之间、树冠下方、巷子远墙），
   整条 band 先铺底色再画细节就没事。
4. **中景机位 y0 决定字幕是否压人**：zoom2 时 caption 顶在 `y0+79`，所以 y0=72 时脚必须 ≤143。
   长镜头会被 shot_report 判"静止"——用一个 0-2px 的缓慢上移（`_push`）解决，肉眼几乎看不出但通过检查。
5. **富士山轮廓**：半宽用 `u**1.3~1.7`（凹形）+ 小平台顶 + 锯齿雪线才对，`u**0.5` 会变成圆形土包。
6. **人物朝向必须与位移方向一致**，否则同手同脚/倒退走。检查每个 walking 镜头的 x 变化方向。
7. 响度：源文件本身很响，`gain_db=+1.4` 会到 -10.4 LUFS / TP+1.7dB（削顶）。
   最终 remux：`-af volume=-2.2dB` → -13.9 LUFS / -1.7 dBTP。

- 直接要成片，不需要每步确认；但中途看方案会提"换风格"，所以一次给多版本更省事。
